## Coding status definitions

- **Supported:** available evidence affirmatively supports the criterion.
- **Contradicted:** available evidence affirmatively conflicts with the criterion.
- **Not established:** the packet does not provide enough evidence to decide; this does not mean the event did not occur.
- **Ambiguous:** the evidence supports materially different interpretations that cannot be resolved from the packet.
- **Not applicable:** use only with a case-specific rationale.

Do not infer an event from a planned artifact. Do not treat the scenario's intended lesson as evidence. Keep observed facts separate from coder interpretation. Each material conclusion must cite an artifact and the relevant detail. If no evidence supports a claim, write what is missing instead of inventing a reference.

## Quality checks before closing the worksheet

- [ ] All cited artifact IDs exist in the packet manifest.
- [ ] Every criterion status has a rationale.
- [ ] Every material claim is grounded in a supplied artifact.
- [ ] “Not established” is not reported as “did not happen.”
- [ ] Authorization is not inferred from passing tests, general PR approval, silence, or deployment alone.
- [ ] Technical correctness, intent alignment, authorization, and evidence sufficiency remain separate.
- [ ] No composite score is calculated.
- [ ] Any change to criterion wording or coding rules is logged and versioned.

## Separation from the reviewer experiment

This worksheet is for the investigator's criterion-by-criterion evidence coding. It does not replace the common reviewer recording sheet and must not be silently added to Condition B. Any decision to expose C1–C20 prompts to reviewers would change the intervention and must be decided and documented before formal evaluation.

No reviewer data are implied by a completed blank template. This worksheet is not a validated instrument.
